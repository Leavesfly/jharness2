# 多用户引擎管理

## 概述

`jharness2-core` 模块负责将单用户的 QueryEngine 封装为支持多用户并发的服务层。核心设计：**Caffeine 缓存池化** + **每用户隔离** + **资源限制保护**。

## 核心组件

### UserContext（用户上下文）

封装单次请求的完整用户信息，作为引擎创建/查找的 Key。

```java
public class UserContext {
    private final String userId;      // 用户标识
    private final String sessionId;   // 会话标识
    private final Path workspace;     // 工作空间路径
    private final String model;       // 使用的模型
    private final String apiKey;      // API 密钥
    private final String baseUrl;     // LLM 服务地址

    // 缓存键：userId:sessionId
    public String getCacheKey() { return userId + ":" + sessionId; }
}
```

### EngineInstance（引擎实例）

包装 QueryEngine，附加生命周期元数据。

```java
public class EngineInstance {
    private final QueryEngine engine;
    private final UserContext userContext;
    private final Instant createdAt;
    private final AtomicReference<Instant> lastAccessedAt;  // 线程安全

    public QueryEngine getEngine() {
        lastAccessedAt.set(Instant.now());  // 每次访问自动更新
        return engine;
    }
}
```

### UserEngineRegistry（引擎注册表）

基于 Caffeine Cache 的引擎池化管理，是多用户并发的核心。

```
┌─────────────────────────────────────────────────┐
│              UserEngineRegistry                  │
│                                                 │
│  ┌──────────────────────────────────────────┐   │
│  │         Caffeine Cache                    │   │
│  │  Key: "userId:sessionId"                  │   │
│  │  Value: EngineInstance                    │   │
│  │                                           │   │
│  │  策略:                                    │   │
│  │  - expireAfterAccess: 30min (空闲超时)    │   │
│  │  - maximumSize: 200 (全局上限)            │   │
│  │  - removalListener: 自动 close()          │   │
│  └──────────────────────────────────────────┘   │
│                                                 │
│  ┌──────────────────────────────────────────┐   │
│  │  ConcurrentMap<userId, AtomicInteger>     │   │
│  │  (每用户引擎计数)                          │   │
│  └──────────────────────────────────────────┘   │
└─────────────────────────────────────────────────┘
```

**核心方法：**

```java
public EngineInstance getOrCreate(UserContext context) {
    // 1. 尝试从缓存获取
    // 2. 缓存未命中 → 检查用户引擎数量限制
    // 3. 超限 → 抛出 EngineLimitExceededException
    // 4. 未超限 → EngineFactory.create() 创建新实例
    // 5. 放入缓存，更新用户计数
}
```

## 资源限制

| 限制项 | 默认值 | 说明 |
|--------|--------|------|
| `maxEnginesPerUser` | 5 | 单用户最大引擎数 |
| `maxTotalEngines` | 200 | 全局最大引擎数 |
| `engineIdleTimeoutMinutes` | 30 | 空闲超时（分钟） |

当用户引擎数超限时，抛出 `EngineLimitExceededException`，由 `GlobalExceptionHandler` 转换为 HTTP 429 响应。

## 引擎工厂

`DefaultEngineFactory` 负责组装完整的 Engine 实例，包含 13 个组件：

```
DefaultEngineFactory.create(UserContext)
│
├── 1. OpenAiClient (LLM 通信)
├── 2. ToolRegistry (内置工具注册)
├── 3. SkillRegistry (技能加载)
├── 4. PluginRegistry (插件加载)
├── 5. System Prompt (系统提示词构建)
├── 6. QueryEngine (核心引擎创建)
├── 7. PermissionChecker (权限系统)
├── 8. MessageCompactionService (消息压缩)
├── 9. AgentOrchestrator (Sub-Agent 协调)
├── 10. McpManager (MCP 协议)
├── 11. HookExecutor (Hook 系统)
├── 12. BackgroundTaskManager (后台任务)
└── 13. SessionPersister (会话自动保存回调)
```

工厂接口可替换：

```java
public interface EngineFactory {
    EngineInstance create(UserContext context);
}
```

## 工作空间隔离

`WorkspaceInitializer` 为每个用户创建独立的文件系统工作空间：

```
./data/workspaces/
├── user_alice/      # 用户 alice 的工作空间
├── user_bob/        # 用户 bob 的工作空间
└── ...
```

**安全措施**：用户名经过 sanitize 处理，仅保留 `[a-zA-Z0-9._-]`，防止路径遍历攻击。

## ChatService（聊天服务）

聊天服务是 Web 层调用 Engine 的门面：

```java
@Service
public class ChatService {
    // 发送消息（异步 + 流式回调）
    public CompletableFuture<Void> chat(UserContext context, String message,
                                        Consumer<ChatEventDto> eventConsumer);
    // 取消正在进行的聊天
    public void cancelChat(String userId, String sessionId);
}
```

## 事件适配

`StreamEventAdapter` 将引擎层的 `StreamEvent` 类型安全地转换为 Web 层的 `ChatEventDto`：

| StreamEvent | ChatEventDto.type |
|-------------|-------------------|
| `AssistantTextDelta` | `"text"` |
| `ToolExecutionStarted` | `"tool_start"` |
| `ToolExecutionCompleted` | `"tool_end"` |
| `AssistantTurnComplete` | `"done"` |
| `UsageReport` | `"usage"` |

使用 Java 17 模式匹配（`instanceof` pattern），无反射开销。

## 生命周期总结

```
用户请求 → getOrCreate()
            ├─ 缓存命中 → 直接使用，更新 lastAccessedAt
            └─ 缓存未命中 → 创建 → 放入缓存
                                    │
                                    ▼
            ┌─────────────────────────────┐
            │  引擎运行中（可多次使用）      │
            └─────────────────────────────┘
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
               空闲超时        容量驱逐         主动关闭
               (30min)       (LRU淘汰)        (close)
                    │               │               │
                    └───────────────┼───────────────┘
                                    ▼
                         removalListener
                         → instance.close()
                         → 释放所有资源
```
